# Wordcraft · 词库扩展方案

## 目标

把目前仅搜索内置示例数据的页面，扩展为两层词库：

1. **在线词典查询**：用户输入任意英文单词并执行搜索时，调用公共 Free Dictionary API（`https://api.dictionaryapi.dev/api/v2/entries/en/<word>`）。在成功响应后，将其规范化为现有详情页所使用的词条结构，展示英文释义、词性、音标、可用音频和例句；若接口无结果或网络不可用，保留友好错误提示，并允许继续查看内置或已导入词。
2. **临时导入词库**：在页面中提供“导入词库”入口。底层采用可扩展的 importer adapter 接口，并先实现 CSV importer。用户可上传 `.csv` 文件，至少支持第一列为 `word` 的格式；可选第二列为 `tag`，用于标记如 CET-4/CET-6。导入内容仅存于当前 React 页面状态，刷新后清空，不写入 localStorage、不需要账户或后端。

## 数据与流程

- 将现有 `entries` 移到独立的本地词库模块，并提供统一的 `normalizeEntry` / `findLocalEntry` 辅助函数。
- 搜索优先查找内置词与当前会话导入词；如果能命中完整本地词条，则立即显示。
- 对没有完整本地详情的单词，发送 API 请求、显示加载状态、成功后渲染动态详情；API 缺少的词形、词源、相关词用“暂未提供”或不显示对应区域处理。
- 对已导入但 API 查询失败的单词，展示最小词条界面（词本身与导入标签），并解释该单词暂无在线词典数据。
- 语音播放优先使用 API 的真实音频 URL；没有音频时回退为浏览器 SpeechSynthesis 生成英式/美式朗读。

## 导入接口

在 `src/lib/importers.js` 定义：

- 通用 importer 约定：`id`、`label`、`accept`、`canImport(file)` 与 `parse(file)`。
- `csvImporter` 读取 UTF-8 CSV（处理表头、空行、英文单词清洗、重复项），返回 `{ entries, warnings }`。
- 保留 importer 注册表；日后加入 JSON、文本粘贴或其他词库格式只需新增适配器，而不改页面导入流程。
- 上传面板显示导入条数、忽略的无效行和重复行；导入的词在侧栏中可见并带上标签。

## 界面调整

- 顶部导航或词条侧栏增加“导入词库”按钮，打开轻量导入面板。
- 搜索区增加加载和失败状态；API 命中时用词条来源标识区分“在线词典”与“导入词库”。
- 词条详情按可用字段渲染，保证 API 返回字段不完整时不会崩溃。

## 验证与文档

- 用内置词、导入的 CSV 单词、API 可识别单词和不存在单词分别验证搜索状态。
- 运行 `npm run build`。
- 更新 README，说明公共 API 依赖、CSV 模板、仅当前会话保存的限制，以及将来扩展 importer 的位置。
